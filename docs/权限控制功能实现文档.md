# 权限控制功能实现文档

## 1. 概述

本项目实现了完整的 RBAC（基于角色的访问控制）权限管理系统，包括：

- ✅ **有权限控制** - 基于角色和权限的访问控制
- ✅ **基于角色的权限控制** - RBAC 模型（用户-角色-权限）
- ✅ **基于方法的权限控制** - 使用自定义注解 `@RequiresPermission` 和 `@RequiresRole`
- ✅ **权限持久化存储** - 权限数据存储在 MySQL 数据库中

---

## 2. 权限控制架构

### 2.1 RBAC 模型

```
用户(User) ←→ 用户角色关联(UserRole) ←→ 角色(Role) ←→ 角色权限关联(RolePermission) ←→ 权限(Permission)
```

### 2.2 数据库表结构

| 表名 | 说明 |
|------|------|
| `sys_user` | 用户表 |
| `sys_role` | 角色表 |
| `sys_permission` | 权限表 |
| `sys_user_role` | 用户角色关联表 |
| `sys_role_permission` | 角色权限关联表 |

### 2.3 默认角色

| 角色代码 | 角色名称 | 说明 |
|----------|----------|------|
| `ROLE_ADMIN` | 管理员 | 拥有所有权限 |
| `ROLE_TEACHER` | 教师 | 可管理学生和成绩 |
| `ROLE_STUDENT` | 学生 | 只能查看信息 |

## 3. 权限控制实现

### 3.1 有权限控制（6分）

#### 实现方式

1. **Spring Security 集成**
   - 配置文件：`SecurityConfig.java`
   - 使用 JWT 进行身份认证
   - 配置请求授权规则

2. **UserDetailsService 实现**
   - 文件：`UserDetailsServiceImpl.java`
   - 从 MySQL 加载用户、角色、权限信息
   - 构建 Spring Security 的 UserDetails 对象

```java
@Override
public UserDetails loadUserByUsername(String username) {
    // 1. 从数据库查询用户
    SysUser user = userMapper.selectOne(...);
    
    // 2. 查询用户的角色列表（从MySQL）
    List<String> roles = userMapper.selectRoleCodesByUserId(user.getId());
    
    // 3. 查询用户的权限列表（从MySQL）
    List<String> permissions = userMapper.selectPermissionCodesByUserId(user.getId());
    
    // 4. 构建UserDetails对象
    return new UserDetailsImpl(user, roles, permissions);
}
```

### 3.2 基于角色的权限控制（8分）

#### 实现方式

1. **自定义角色注解**
   - 文件：`@RequiresRole`
   - 支持 AND/OR 逻辑

```java
@RequiresRole("ROLE_ADMIN")  // 需要管理员角色
@RequiresRole(value = {"ROLE_ADMIN", "ROLE_TEACHER"}, logical = Logical.OR)  // 管理员或教师
```

2. **角色管理 API**
   - Controller：`RoleController.java`
   - Service：`RoleService.java`
   - 功能：增删改查角色、分配权限、分配角色给用户

#### 示例代码

```java
@GetMapping("/user/{userId}")
@RequiresRole(value = {"ROLE_ADMIN", "ROLE_TEACHER"}, logical = RequiresRole.Logical.OR)
public Result<List<RoleVO>> getRolesByUserId(@PathVariable Long userId) {
    // 只有管理员或教师可以查看用户角色
}
```

### 3.3 基于方法的权限控制（9分）

#### 实现方式

1. **自定义权限注解**
   - 文件：`@RequiresPermission`
   - 支持 AND/OR 逻辑

```java
@RequiresPermission("student:add")  // 需要添加学生权限
@RequiresPermission(value = {"student:view", "student:edit"}, logical = Logical.OR)  // 查看或编辑权限
```

2. **AOP 权限切面**
   - 文件：`PermissionAspect.java`
   - 拦截带有 `@RequiresPermission` 和 `@RequiresRole` 注解的方法
   - 校验用户是否拥有所需权限/角色

```java
@Around("@annotation(com.student.system.annotation.RequiresPermission)")
public Object checkPermission(ProceedingJoinPoint joinPoint) throws Throwable {
    // 1. 获取注解信息
    RequiresPermission annotation = method.getAnnotation(RequiresPermission.class);
    
    // 2. 获取当前用户的权限列表
    UserDetailsImpl userDetails = (UserDetailsImpl) authentication.getPrincipal();
    List<String> userPermissions = userDetails.getPermissions();
    
    // 3. 校验权限
    boolean hasPermission = checkPermissions(userPermissions, requiredPermissions, logical);
    
    // 4. 权限不足则抛出异常
    if (!hasPermission) {
        throw new AccessDeniedException("权限不足");
    }
    
    return joinPoint.proceed();
}
```

3. **权限管理 API**
   - Controller：`PermissionController.java`
   - Service：`PermissionService.java`
   - 功能：增删改查权限

#### 应用示例

在 `StudentController.java` 中：

```java
@PostMapping("/add")
@RequiresPermission("student:add")
public Result<String> addStudent(@Valid @RequestBody StudentDTO studentDTO) {
    // 只有拥有 student:add 权限的用户才能添加学生
}

@GetMapping("/list")
@RequiresPermission("student:view")
public Result<IPage<Student>> listStudents(...) {
    // 只有拥有 student:view 权限的用户才能查看学生列表
}

@DeleteMapping("/{id}")
@RequiresPermission("student:delete")
public Result<String> deleteStudent(@PathVariable Long id) {
    // 只有拥有 student:delete 权限的用户才能删除学生
}
```

### 3.4 权限持久化存储在数据库或者别的中间件中（10分）

#### 实现方式

1. **MySQL 存储**
   - 所有权限数据存储在 MySQL 数据库
   - 表结构：`sys_permission`、`sys_role`、`sys_user_role`、`sys_role_permission`

2. **权限初始化 SQL**
   - 文件：`init-mysql/permission-init.sql`
   - 预置系统权限和角色数据

```sql
-- 插入权限数据
INSERT INTO `sys_permission` (`permission_name`, `permission_code`, `resource_type`, `url`, `method`, `description`) VALUES
('查看学生', 'student:view', 'api', '/student/**', 'GET', '查看学生信息'),
('添加学生', 'student:add', 'api', '/student/add', 'POST', '添加新学生'),
('编辑学生', 'student:edit', 'api', '/student/update', 'PUT', '编辑学生信息'),
('删除学生', 'student:delete', 'api', '/student/{id}', 'DELETE', '删除学生');

-- 为角色分配权限
INSERT INTO `sys_role_permission` (`role_id`, `permission_id`)
SELECT 
    (SELECT id FROM sys_role WHERE role_code = 'ROLE_ADMIN'),
    id
FROM sys_permission;
```

3. **动态权限加载**
   - 用户登录时从数据库加载权限
   - 支持动态修改权限，无需重启应用

## 4. API 接口

### 4.1 权限管理接口

| 接口 | 方法 | 路径 | 说明 | 需要权限 |
|------|------|------|------|----------|
| 添加权限 | POST | `/permission/add` | 添加新权限 | `system:permission:add` |
| 更新权限 | PUT | `/permission/update` | 更新权限信息 | `system:permission:edit` |
| 删除权限 | DELETE | `/permission/{id}` | 删除权限 | `system:permission:delete` |
| 查询权限 | GET | `/permission/{id}` | 查询权限详情 | `system:permission:view` |
| 权限列表 | GET | `/permission/list` | 分页查询权限 | `system:permission:view` |
| 所有权限 | GET | `/permission/all` | 查询所有权限 | 无 |

### 4.2 角色管理接口

| 接口 | 方法 | 路径 | 说明 | 需要权限 |
|------|------|------|------|----------|
| 添加角色 | POST | `/role/add` | 添加新角色 | `system:role:add` |
| 更新角色 | PUT | `/role/update` | 更新角色信息 | `system:role:edit` |
| 删除角色 | DELETE | `/role/{id}` | 删除角色 | `system:role:delete` |
| 查询角色 | GET | `/role/{id}` | 查询角色详情 | `system:role:view` |
| 角色列表 | GET | `/role/list` | 分页查询角色 | `system:role:view` |
| 所有角色 | GET | `/role/all` | 查询所有角色 | 无 |
| 分配权限 | POST | `/role/assign-permissions` | 为角色分配权限 | `system:role:assign` |
| 分配角色 | POST | `/role/assign-to-user` | 为用户分配角色 | `system:user:assign-role` |
| 用户角色 | GET | `/role/user/{userId}` | 查询用户的角色 | `ROLE_ADMIN` 或 `ROLE_TEACHER` |

## 5. 使用示例

### 5.1 初始化权限数据

```bash
# 执行权限初始化SQL
mysql -u student_user -p student_sys < init-mysql/permission-init.sql
```

### 5.2 登录获取 Token

```bash
curl -X POST http://localhost:8080/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "username": "admin",
    "password": "admin123"
  }'
```

响应：
```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "roles": ["ROLE_ADMIN"],
    "permissions": ["student:add", "student:view", ...]
  }
}
```

### 5.3 使用 Token 访问受保护接口

```bash
# 添加学生（需要 student:add 权限）
curl -X POST http://localhost:8080/student/add \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "studentNo": "2024001",
    "name": "张三"
  }'
```

### 5.4 添加新权限

```bash
curl -X POST http://localhost:8080/permission/add \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "permissionName": "导出学生",
    "permissionCode": "student:export",
    "resourceType": "api",
    "url": "/student/export",
    "method": "GET",
    "description": "导出学生数据"
  }'
```

### 5.5 为角色分配权限

```bash
curl -X POST http://localhost:8080/role/assign-permissions?roleId=2 \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '[1, 2, 3, 4, 5]'
```

### 5.6 为用户分配角色

```bash
curl -X POST http://localhost:8080/role/assign-to-user \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "userId": 10,
    "roleIds": [2, 3]
  }'
```

### 6.2 角色命名规范

## 7. 权限校验流程

```
1. 用户登录
   ↓
2. 从数据库加载用户的角色和权限
   ↓
3. 生成 JWT Token（包含用户信息）
   ↓
4. 用户访问受保护接口
   ↓
5. JWT 过滤器验证 Token
   ↓
6. AOP 切面拦截方法
   ↓
7. 检查用户是否拥有所需权限/角色
   ↓
8. 权限不足 → 抛出 AccessDeniedException
   权限通过 → 执行业务逻辑
```

## 10. 注意事项

1. **开发环境配置**
   - 当前 `SecurityConfig` 中临时放行了 `/student/**` 和 `/score/**`
   - 生产环境部署前需要移除这些放行规则

2. **权限粒度**
   - 可以根据实际需求调整权限粒度
   - 支持 API 级别、方法级别、数据级别的权限控制

3. **性能优化**
   - 可以考虑将权限数据缓存到 Redis
   - 减少数据库查询次数

4. **安全建议**
   - 定期审计权限分配
   - 遵循最小权限原则
   - 敏感操作添加二次验证
